What it demonstrates

  • Learns required connection context when it is first needed.
  • Adapts to incremental corrections about priority, inactive status, donor reserve, and approvals.
  • Uses relevant prior feedback naturally without asking users to manage memories.
  • Produces read-only, evidence-backed recovery recommendations.

Connection context

Environment, role, and device headers come from the current conversation or relevant prior context. Basic Auth remains environment-local.

Agent Memory

The user works normally and corrects the agent one rule at a time; relevant corrections are applied silently in a fresh chat.

Prerequisites

  • Private Agent Factory 26.7-compatible environment with Agent Memory and cross-thread sharing enabled.
  • Network access to JDE AIS plus an available LLM connection.
  • JDE Basic Auth user with read access to F4211, F4201, F41021, F4311, F4101, and F0101.

Safety controls

  • The OpenAPI definition exposes GET operations only.
  • Last-status-900 lines are excluded after the user teaches that rule.
  • Donors must retain the learned 1,000-unit indicative balance.
  • JDE-changing actions require approval; every live response confirms no change was made.

Import and configure

  1. Create a REST source from assets/jde-fulfillment-openapi.json, verify its AIS URL, and configure Basic Auth.
  2. Download and import the release PAF, then rebind the REST API Tools node and select a model.
  3. Enable Agent Memory and cross-thread sharing for the same user.
  4. Delete any prior playground memories for the test user, then run both sessions.

Session 2 — silent continuity

User

Can you review today's backorders, tell me what we should tackle first, and give me the best cross-branch backup if its local branch cannot cover it? Show me the numbers and keep it aligned with how our team operates.

Expected outcomes

  • The fresh chat does not ask again for relevant connection values.
  • Status-900 lines are excluded and the earliest requested active line is prioritized.
  • Donor-floor arithmetic is explicit and approval remains mandatory.
  • The response ends with: JDE changes made: none (read-only analysis).

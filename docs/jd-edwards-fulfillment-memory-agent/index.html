What it demonstrates

  • Recalls a user-specific JDE execution context across sessions.
  • Recalls and enforces an explicitly named recovery policy.
  • Shows post-transfer donor-cushion arithmetic before recommending cross-branch stock.
  • Keeps every JDE-changing action behind explicit human approval.

Connection context

The end user supplies environment, role, and device values; the agent recalls them from a named operating profile. Basic Auth remains environment-local.

Agent Memory

The user deliberately establishes a named profile, then the agent recalls its connection context and operating policy in a fresh chat.

Prerequisites

  • Private Agent Factory 26.7-compatible environment with Agent Memory and cross-thread sharing enabled.
  • Network access to JDE AIS plus an available LLM connection.
  • JDE Basic Auth user with read access to F4211, F4201, F41021, F4311, F4101, and F0101.

Safety controls

  • The OpenAPI definition exposes GET operations only.
  • The 1,000-unit post-transfer donor floor is applied numerically.
  • Anything that could change JDE requires explicit human approval.
  • Learned memory records are user-specific runtime data and are never packaged.

Import and configure

  1. Create a REST API source from assets/jde-fulfillment-openapi.json, verify the AIS URL, and configure Basic Auth.
  2. Download and import the release PAF, then rebind its REST API Tools node and select a model.
  3. Enable Agent Memory and cross-thread sharing for the same user.
  4. Run both demo sessions as the same user, starting from clean memories.

Tested demo flow

Session 1 — establish the named profile

User

Hi, I'm taking over the North America fulfillment review. Let's call this the North America Fulfillment Standard. For this JDE connection, use environment JPS920, role *ALL, and device ops-fulfillment-demo. Please remember that for future chats. I'm only setting up today, so don't query JDE yet.

User

One more rule for that standard: a cross-branch candidate is eligible only when it addresses the earliest requested active line and leaves at least 1,000 units of indicative available balance in the donor branch after the proposed allocation. Anything that could change JDE needs explicit human approval. Please remember that too.

Session 2 — recall and apply

User

Morning. Which JDE environment is saved in my North America Fulfillment Standard? Answer from memory only; do not query JDE.

User

What role and device identifier are saved for that same standard? Answer from memory only; do not query JDE.

User

Before we look at today's orders, remind me of the saved cross-branch eligibility rule and the approval control for that standard. Please do not query JDE yet.

User

Great—use that remembered standard to run today's fulfillment exception review. Find up to five backordered sales-order lines, determine which order deserves investigation first, and recommend the single best eligible cross-branch recovery action. Show the post-allocation cushion arithmetic and do not change JDE.

Expected outcomes

  • The fresh chat recalls all connection values and policy constraints.
  • Donors below the remembered 1,000-unit floor are rejected with arithmetic.
  • The analysis makes no JDE changes.
